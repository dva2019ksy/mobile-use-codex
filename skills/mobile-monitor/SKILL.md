# 移动设备操作与监看

mobile-use-codex 同时包含两个服务：`mobile-use-codex` 提供监看和操作租约，`mobile-control` 提供上游 mobile-mcp 的 `mobile_*` 操作工具。使用本插件内的工具即可，不要求用户另外安装或配置 mobile-mcp。若环境还有独立 mobile-mcp 的同名工具，优先选择本插件 `mobile-control` 来源；不要跨来源重复执行同一动作。

## 设备与操作

- 先用内置 `mobile_list_available_devices` 获取实际在线设备，按用户要求选择，每个操作显式传入 `device`，不存在隐式的“当前设备”。监看服务的 `list_devices` 也可用于设备发现。多个候选设备无法区分时再询问，不猜设备 ID、平台、账号状态或 App 包名。优先使用本地设备，只有本地设备不满足任务或用户要求时才使用远程云设备。远程设备收费，分配和释放需要时间；整个任务结束后以 finally 式清理调用 `mobile_release_remote_device`，使设备清理并归还资源池，不在同一任务的步骤之间释放并重新分配。
- 设备操作开始前调用 `open_monitor`，保存返回的 `operation`，在同一任务中复用监看。仅查询可用设备时不必启动采集。后续动作调用本插件内置的 `mobile_*` 工具。
- 用 `mobile_list_elements_on_screen` 读取当前页面，优先使用最新元素 ref；元素树缺失目标或需要视觉判断时再用 `mobile_take_screenshot`。截图坐标按工具返回的比例换算。跳页、滚动、弹窗或旋转后重新观察。
- 用 `mobile_list_apps` 确认应用标识后再 `mobile_launch_app`；打开网页优先用 `mobile_open_url`。后者默认只接受 HTTP/HTTPS，只有服务启动时显式设置 `MOBILEMCP_ALLOW_UNSAFE_URLS=1` 才放宽协议限制；不猜测或依赖未支持的 App 深链接。
- 同一设备的动作串行执行，采用自然节奏；一般交互之间留出约 0.6–1.5 秒，工具耗时已提供足够间隔时不重复等待。一次滑动一屏以内，页面稳定后再判断。
- 输入前确认焦点及已有内容。普通文字分短段输入，手机号或验证码逐字符输入，每段约间隔 0.2–0.6 秒；核对完整内容后再提交。按实际工具 schema 使用 `submit`，不编造输入速度参数。批处理仅用于已知且无需中间判断的短序列，不跨越支付、下单或发送等需要核对的动作。
- 设备画面用于用户观看，不能替代 Agent 读取元素树或必要截图。购物、支付、账号登录及发送消息遵循当次任务授权；已有设备专属上下文或 skill 时按需使用，不把某台设备的账号信息套用到其他设备。

## 右侧实时面板

`open_monitor` 默认请求 Codex 的 `fullscreen` 显示模式，在当前客户端中对应右侧面板。widget 加载后至多补一次展开请求；用户主动收回后不反复弹开。侧栏开关使用客户端原生入口，面板工具栏不提供展开/收起按钮。不请求 PiP，也不通过 CUA 触发原生浮窗。

首次保持默认 30 fps、0.5 缩放，区分采集与显示帧率。勿循环调用 `open_monitor` 刷新画面。`read_frame` 和 `release_frame_viewer` 仅供 widget 使用，Agent 不循环调用它们。原生 widget 通过 MCP 工具桥传帧，本地 HTTP 页面只用于诊断。

区分工具成功、widget 加载和收到真实设备帧；只有实际观察到实时画面时才报告 UI 验证通过。设备未就绪时依据实际错误处理连接、配对或设备端 agent，不把安装插件等同于设备准备已完成。

## 操作租约与单例采集

`open_monitor` 创建或续用当前监看连接的主要租约。额外独立操作可用 `begin_operation` 创建独立租约；操作持续时每约 45 秒 `renew_operation`，避免 90 秒租约到期。不要靠 widget 轮询续租。

**在本轮设备任务成功、失败、取消、暂停或等待用户回复前，以 finally 式清理调用 `end_operation`，释放自己持有的全部租约，然后再答复。** 用户明确要求测试期间持续采集时，可在等待该测试反馈期间保留并续租；测试结束仍释放租约。

所有连接按设备 ID 共用一个采集实例；最后一个活动操作释放后停止采集，其他会话仍有活动操作时继续。观看者不会维持采集；采集结束后面板停止轮询并请求自动关闭，不支持关闭接口的客户端退回 inline、收起侧栏。暂停画面时仍会检查任务结束状态。`close_monitor` 只结束本连接的操作，不影响其他连接；`monitor_status` 不启动采集。监看暂停/继续不会在零活动操作时自行启动采集。

面板底部提供 Home、音量加减和暂停/继续。Home 与音量使用仅向 widget 开放的 `press_monitor_button`，只允许本连接仍持有设备操作租约时执行，不创建或续租操作。Agent 的设备操作仍使用内置 `mobile_*` 工具。本地 HTTP 诊断页只读，不提供硬件按键操作。

内置操作服务与监看服务分别运行。操作工具不会自动创建或结束监看租约，也不能从单个工具调用推断整个任务结束；本 skill 负责在设备任务外围协调租约，超时仅作异常兜底。不要循环开启监看、启动额外诊断采集或在任务结束后仅等待租约超时。
